做出海网站的朋友应该都懂，外链这件事不难但是烦。

找导航站、注册账号、等验证邮件、填一遍又一遍差不多的表单、回头再记到表格里。像这种重复性工作现在人是干不了一点了，必须自动化掉。之前用的是 Codex 来做，跑在 Mac Mini 上，可以做但是太慢了，经常会卡住。

最近 Grok Bot 特别火，也确实好用，速度快，操作云端服务器也不会影响自己干活。就让它接手来了这件事。

这篇把整套流程、踩过的坑和目前的真实数据分享给大家。希望这套工作流能帮助大家解放双手。

## 一、先说分工：人做决定，bot 做重复

再说一下 Grok Bot 有几个特点刚好适合干外链：它有自己的电脑和浏览器，能自己打开网页填表；有自己的邮箱，能收验证码；还能设定时任务，每天固定时间自己开工。

首先明确：哪些事可以交出去，哪些事必须留在我手里。

**交给 bot 的**，全是规则明确、错了也无妨的重复劳动：去重、排序、查重、注册、填表、收邮件、记表格、发日报、查收录。

**留在手里的**只有两类：名单，以及所有涉及钱、手机号、身份信息的事。顺便说一下，目前我只让他发免费的外链。

这个边界是整个流程能放心跑起来的前提。bot 不会自作主张替我花一分钱。

**整体流程：**

1. 我导出导航站清单 → 交给 bot\
2. bot 去重、筛选、按价值排队\
3. bot 用统一的“提交素材包”填表（链接带 UTM）\
4. 验证邮件同时转发到我和 bot 的邮箱，bot 自己收码、点链接\
5. bot 回写飞书表格，每天推送日报卡片，每周复查收录\

下面按搭建的顺序说，有几步是踩了坑才定下来的。

## 二、第一步：把外链清单交给 bot，让它排出一个队列

我手里的外链资源基本都是各种渠道导出的表格。

丢给 bot，它做三件事：跟我们飞书多维表格里已有的导航站列表比对去重，排除之前审批过的候选站；只保留免费且被标记为推荐的站点；按推荐等级和 Domain Rating（DR）排队。

bot 按价值顺序去做。

## 三、第二步：准备一份“提交素材包”，外加一份“禁写清单”

填过导航站表单的人都知道，每个站要的字段都不太一样：有的要 60 字以内的一句话介绍，有的要 160 字描述，有的还要现场回答几个问题。让 AI 每次现场发挥，结果一定忽长忽短、口径不一。

所以我一次性准备了一份素材包，bot 填表时直接从里面取：

- 产品名称\
- 标语：60 字符和 40 字符两个版本\
- 描述：100 / 160 / 250 字符三个版本，外加一个长版本\
- 分类、标签\
- Logo、产品截图\
- 常见问答的标准回答\

光有“该写什么”还不够。我还给了一份“不要写”清单：

- 不要用过时的数据；\
- 不要填个人 X 账号。\

这些都是根据自己的网站情况来定的。

另外，每个提交出去的网址都带 UTM 参数：

```
?utm_source=<名称>&utm_medium=directory&utm_campaign=backlinks
```

这样以后在统计后台能看清哪个导航站真的带来了流量，外链的价值最终要用流量说话，不能只看收录。

**这一步的心得：** 给 AI 的指令，写清楚“不要做什么”和写清楚“要做什么”一样重要。

## 四、第三步：每个工作日下午，bot 自己去提交 5 个站

我给 bot 设了定时任务：每个工作日下午，从队列取出下一批 5 个免费站点开工。

每个站点它会先查重，用站内搜索或者 `site:` 搜索确认是不是已经被收录过，有了就跳过。

然后判断能不能做：付费才能提交的、只支持 Google 登录的、要求写文章投稿的内容 / 媒体类、应用市场类站点，一律跳过。

最后，用产品的客服邮箱注册账号，密码自己生成、存在本地凭据文件里，在它自己的浏览器里把表单填完、提交。

5 个站这个量是我故意限制的。也可以加量，自己判断。

## 五、最烦人的是验证邮件，这一步必做

这一部分是整个流程里我最想分享的，因为它曾是最大的卡点。

我们域名下的 `support@` 邮箱其实不是真正的邮箱，是用 Cloudflare Email Routing 做的转发。问题在于：一条转发规则只能设一个目标地址。
![image](https://pub-8dc0158e77a140d4b502b52ab75765b5.r2.dev/docs/a60c9b88cf27dabc.jpg)


于是之前的情况是：bot 在注册，验证码和确认链接却发到了我的邮箱。我得盯着收件箱，看到一封手动转给 bot。很烦不说，有些 magic link（一次性登录链接）有效期很短，等我转过去已经过期了，只能重来。

**解法**是写一个 Cloudflare Email Worker，几行 JS，把一封信同时转发给两个地址：

```js
export default {
  async email(message, env, ctx) {
    await message.forward("you@yourcompany.com");
    await message.forward("bot@your-bot-inbox.com");
  }
}
```

（地址换成你自己的。）
![image](https://pub-8dc0158e77a140d4b502b52ab75765b5.r2.dev/docs/d0f9dd71ab6c75b3.jpg)


有个前提：转发目标需要先在 Cloudflare 里验证。

配好以后我发了封测试邮件，两个邮箱都收到了。效果立竿见影：当天 bot 注册登录，几秒内从自己的邮箱拿到 6 位验证码，自己完成了登录，全程不需要我插手了。

> 注：Grok 那边的域名邮箱地址是 `@mail.grokbot.com`，没有领的可以去领一个。

## 六、提交完不记录等于没做：回写飞书 + 每天一张日报卡片

记录这部分也全交给了 bot：

- **每次成功提交后**：在飞书表格里勾选该站点，填写发布日期，在备注里追加一条带日期的记录，写明状态和是否用了 UTM。注意是追加，从不覆盖原有备注。\
- **卡住的、要付费的、在排队的**：统一放进一个待处理清单。\
- **固定时间点**：通过机器人 Webhook 往团队飞书群推送一张交互卡片，包括 4 个数据块（今日发布数、免费数、付费数、总花费）、今天成功上线的列表、需要人来处理的事项。\
- **每周一**：复查每个已提交站点的收录状态，把状态、收录页链接、检查时间写回表格，再推送一张周报卡片。\

备注只追加、不覆盖，是我从以前的教训里定下的规矩。哪天出问题回头追溯，有完整的时间线就很好查。

一个小提醒：飞书卡片有元素数量限制，挑关键的上卡片，细节留在表格里。

我每天只需要看一眼群里的卡片，处理最下面那几条“需要人工”的事。

## 七、一周下来踩过的坑

除了上面说的，还有几个值得记下来：

- 很多“免费”是有条件的。有的站只收费；有的要求你在自己网站上挂徽章。比如 TinyLaunch 的免费发布，要进入前三名并且嵌入徽章才给外链，而且排期已经排到 11 月 30 日。\
- 有些门槛 bot 不该替你跨。TrustRadius 要求 LinkedIn 公司主页有 10 名以上员工，SoftwareSuggest 需要手机号。这类涉及身份的事，一律留给人来决定。\
- 只支持 Google 登录的站直接跳过，不值得为此让 bot 绑定个人账号。\
- 永远先查重再提交。重复提交浪费时间，有的站还会因此拒绝你。
