> 用 AI 快速搭建网站后，部署到 Vercel 并不意味着 Google 就能正常收录。如果网站存在渲染问题、Sitemap 缺失、robots.txt 配置错误或页面被设置为 noindex，即使内容写得不错，也可能迟迟没有搜索流量。上线前花半小时检查 7 项基础 SEO 设置，可以提前发现不少技术问题，减少网站上线后才排查的麻烦。

## 一、为什么 AI 搭建的网站上线后，Google 还是搜不到？

现在用 Vibe Coding 开发网站，速度确实快。借助 AI 写好前端，再部署到 Vercel，一个网站可能几天就能上线。

但网站能够正常打开，不代表 Google 就能正常抓取和收录。

我见过不少新手把注意力全放在页面设计、功能和内容上，却忽略了 SEO 基础配置。网站上线一个月，Google Search Console 里的展示量还是零，才开始怀疑是不是内容质量不行。

实际上，**网站没有流量，不一定是内容差，也可能是搜索引擎根本没有正确抓取页面。**

尤其是使用 AI 生成项目时，开发者可能直接沿用脚手架配置，没有检查渲染方式、索引设置和页面状态。这些问题在本地开发时不一定能发现，却可能影响网站上线后的搜索表现。

上线前，我建议先检查下面这 7 项。

## 二、上线前必须检查的 7 项 SEO 设置

### 1. 检查页面渲染方式

如果你使用 React、Vue 等技术搭建网站，需要确认页面内容是否能被 Google 正常获取。

纯客户端渲染（CSR）依赖 JavaScript 在浏览器中生成页面内容。Google 可以执行 JavaScript，但渲染过程可能需要额外时间，也可能受到资源加载失败等问题影响。

因此，对于需要通过自然搜索获取流量的网站，SSR（服务端渲染）或预渲染通常更容易让搜索引擎直接获取完整的页面 HTML。

这里并不是说所有网站都必须使用 SSR。如果页面已经通过静态生成（SSG）输出了完整 HTML，同样可以满足需求。

上线后，可以使用 Google Search Console 的网址检查工具查看实际抓取结果，并检查渲染后的 HTML 中是否包含页面正文、标题和主要链接。

### 2. 生成 Sitemap.xml 并提交给 Google

Sitemap（站点地图）用于告诉搜索引擎，网站上有哪些值得发现的页面。

如果网站有博客、产品详情页或大量动态路由，建议自动生成 Sitemap，而不是每次新增页面都手动维护。

例如，使用 Next.js 搭建的博客，可以通过框架支持的 Sitemap 配置，自动输出文章列表、产品页面等规范 URL。新增文章后，站点地图也应随之更新。

生成后，先检查 `https://你的域名/sitemap.xml` 是否可以正常访问，再到 Google Search Console 提交 Sitemap。

需要注意，**提交 Sitemap 不等于 Google 一定会收录所有页面**。它主要帮助 Google 发现 URL，页面能否被收录还取决于抓取条件、内容质量和索引规则。

### 3. 检查 robots.txt 有没有屏蔽搜索引擎

robots.txt 用于控制爬虫可以抓取哪些路径。

开发过程中，为了避免测试页面被抓取，有些项目会配置禁止爬虫访问的规则。如果上线时没有调整，正式网站也可能继续屏蔽 Googlebot。

检查网站根目录下的 `https://你的域名/robots.txt`，确认规则是否符合预期，尤其要留意是否存在全站禁止抓取的配置。

例如：

```txt
User-agent: *
Disallow:
Sitemap: https://example.com/sitemap.xml
```

这只是一个允许抓取的基础示例，实际配置还需要根据网站结构调整。

另外，robots.txt 和 noindex 不是一回事。前者主要控制抓取，后者用于表达页面不应被索引。如果页面被 robots.txt 屏蔽，Google 反而可能无法读取页面中的 noindex 指令，所以不要把两者混用。

### 4. 全站检查 noindex 设置

这是上线前很容易遗漏的一项。

部分项目在测试阶段会给页面添加 `noindex`，避免开发环境被搜索引擎收录。如果发布正式环境时没有清理，页面就可能继续被要求不要进入搜索索引。

检查页面 HTML 中是否存在：

```html
<meta name="robots" content="noindex">
```

也要检查 HTTP 响应头中是否设置了 `X-Robots-Tag: noindex`。

如果使用 Next.js、React 或其他框架，还需要检查相关组件、布局和环境变量，确认没有通过代码统一添加 noindex。

但不要直接删除全站所有 noindex。登录页、内部管理页、测试页面等可能本来就不需要被搜索引擎收录。正确做法是确保需要获得自然搜索流量的正式页面没有被意外屏蔽。

### 5. 清理重定向问题和失效链接

网站改版、更换域名或调整 URL 结构后，容易出现重定向链、错误跳转和失效链接。

例如，用户访问一个旧地址，需要经过两三次跳转才能到达最终页面。这不仅增加访问成本，也会让网站维护变得复杂。

上线前，建议检查重要页面的 HTTP 状态码，确认正常页面返回 200，已经永久迁移的页面使用合理的 301 重定向，而不存在的页面返回真正的 404 状态码。

如果某篇文章更换了地址，应将旧 URL 直接重定向到最相关的新页面，而不是把所有失效链接统一跳转到首页。

404 页面可以设计得友好一些，例如提供搜索框、相关内容或返回首页的入口。但要注意，**页面看起来友好，不代表状态码就可以错误地返回 200**。不存在的页面仍应正确返回 404，避免产生软 404 问题。

### 6. 检查每个重要页面的 Title 和 Description

网站可以被抓取，也不代表页面已经具备良好的搜索展示条件。

每个重要页面都应该有明确的标题，准确说明页面主题。Meta Description 则可以概括页面内容，帮助用户理解点击后能获得什么。

例如，做 AI 图片生成工具的网站，不要让所有页面都使用同一个标题，例如“AI Image Generator”。首页、定价页、功能页和教程页应该根据各自内容设置不同的标题。

同时，检查页面是否存在标题缺失、重复标题、描述为空等问题。对于博客和产品网站，可以通过模板自动生成基础 SEO 元数据，再针对重点页面进行人工优化。

需要注意，Google 可能根据搜索查询自动生成标题链接和摘要，不一定完全采用你设置的 Title 和 Description。设置它们的目的，是让页面主题更清晰，而不是保证某个固定文案一定出现在搜索结果中。

### 7. 检查规范 URL 和内部链接

同一页面可能通过多个 URL 被访问，例如带有追踪参数的链接、不同的路径形式，或者 HTTP 与 HTTPS 地址。

如果没有合理处理，搜索引擎可能需要判断哪些 URL 才是主要版本。

对于内容页面，应根据实际情况设置正确的 canonical（规范 URL），指向希望作为主要版本的地址。不要把所有页面都错误地指向首页，也不要在规范地址配置中混用不同域名或协议。

同时检查网站内部链接是否正常。首页、分类页、产品页和文章之间应该有清晰的链接关系，重要页面不能只存在于 Sitemap 中，却没有任何正常页面链接指向它们。

如果网站有大量博客文章，可以通过分类页、相关文章和面包屑导航帮助用户及搜索引擎发现内容。

## 三、上线前的 SEO 自查清单

这 7 项检查可以整理成一份简单的上线流程。每次新站部署完成后，逐项确认即可。

- [ ] 页面能够输出或正确渲染主要内容，SSR、SSG 或 CSR 方案符合实际需求。
- [ ] Sitemap.xml 可以正常访问，重要页面已包含其中，并已提交 Google Search Console。
- [ ] robots.txt 没有意外屏蔽需要抓取的页面。
- [ ] 重要页面没有被意外设置为 noindex。
- [ ] 重定向、404 状态码和内部链接正常。
- [ ] 重要页面拥有合适的 Title 和 Meta Description。
- [ ] canonical 和内部链接配置正确，重要页面可以被正常发现。

检查这些项目通常不需要很长时间，但如果等到网站上线几个月后才发现配置错误，排查成本可能更高。

最后还要做一步：在 Google Search Console 中检查重点 URL，查看抓取情况、索引状态和搜索展示数据。如果网站刚刚上线，暂时没有流量并不一定意味着存在技术错误，Google 发现、抓取和索引新页面都需要时间。

**网站上线只是开始。先确保搜索引擎能够正确发现、抓取和理解页面，再去分析内容质量与关键词竞争，排查问题会更有方向。**
